# mbspost: post-processing for OpenModelica gear trains, camtrains and drivelines

`mbspost.py` reads OpenModelica results of models built from the `GearMeshBenchmark` components. It works out forces, torsional dynamics, order spectra and modes for every component, then writes an HTML report and CSV tables. It finds the components by their variables, so it works for any system assembled from them, whatever the instance names or nesting depth.

## Files
| File | Purpose |
|---|---|
| `mbspost.py` | the library: result reader, OpenModelica runner, component discovery, metrics, plots, modes, Campbell, sweeps, HTML report |
| `run_postprocessing.py` | command-line front end |
| `PostProcessing_Workflow.ipynb` | guided workflow on Stage 1, Stage 2 and the camtrain demo, with a metric glossary |
| `example_reports/` | HTML reports generated by the notebook |

Requires `numpy scipy matplotlib pandas`, plus OpenModelica (`omc`) if Python should compile and run the models. Results simulated in OMEdit can be loaded directly instead.

## Workflow
1. **Model.** Assemble the components in Modelica and expose the parameters you want to vary as top-level parameters.
2. **Run.** `OMRunner(mo, model).build()` compiles once. `simulate(overrides={...})` then re-runs in about 0.1–2 s without recompiling. Alternatively, simulate in OMEdit and load the result with `OMResult('..._res.mat')`.
3. **Discover.** `System(res)` lists every gear mesh, bearing, support, torsion element, body and load.
4. **Metrics.** `report(revs=(3, None))` computes metrics per component in a steady-state window, given in seconds or in reference revolutions.
5. **Signals.** `report.figures()`, `torsional_overview()` and `force_overview()` produce time plots, load and journal orbits, and order spectra on the driver or crank angle.
6. **Modes.** `runner.modes(t_lin, overrides={'jn': 1e-7, 'clr_x': 0})` linearises in a loaded state and returns frequency, damping and kinetic-energy share per DOF. `campbell()` adds the diagram and a table of resonance speeds.
7. **Compare.** `sweep(runner, 'jn', values)` and `compare_reports()` collect metric trends. `to_html()` and `to_csv()` export the results.

```python
import mbspost as mp
r = mp.OMRunner('../openmodelica/GearMeshBenchmark.mo', 'GearMeshBenchmark.Examples.GearTrain3')
r.build()
rep = mp.System(r.simulate()).report(revs=(3, None))
rep.table('GearMesh2D')
rep.to_html('report.html', modes=r.modes(0.05, overrides={'jn': 1e-7, 'clr_idler': 0}))
```

Command line:
```
python run_postprocessing.py --mat <result.mat> --revs 3 --out my_report
python run_postprocessing.py --mo ../openmodelica/GearMeshBenchmark.mo --model GearMeshBenchmark.Examples.GearTrain3 \
       --set jn=0.08e-3 --revs 3 --modes 0.05 --lin-set jn=1e-7 clr_idler=0 --orders 1 2 4 20 --rpm 0 8000
```

`omc` is looked up in the `OMC_PATH` environment variable, then in `PATH`, then in common install folders. You can also pass it explicitly with `OMRunner(..., omc='/path/to/omc')`.

## Metrics (summary; full glossary in the notebook)
| Component | Main metrics |
|---|---|
| GearMesh2D | tooth force statistics, dynamic factor, contact/separation time shares, impacts per flank, flank changes, tooth deflection, free play, dynamic transmission error, damping energy |
| RadialBearingClearance | resultant and x/y force statistics, peak load direction, journal eccentricity and clearance use, contact share, impacts, friction power |
| NonlinearSupport2D, SpringDamper2D | reaction force statistics and orbits, support deflection |
| TorsionSpringDamper | torque statistics, twist, dynamic factor, dominant order |
| Body, PointMass | mean speed, speed irregularity, angular acceleration, inertia torque, centre motion |
| Modes | eigenfrequency, damping, torsional/lateral classification, energy per DOF, Campbell resonance speeds |

## Modelling rules that keep post-processing robust
* **Expose parameters at top level.** Make every parameter you want to sweep a top-level parameter. OpenModelica cannot override parameters bound to other parameters, and `OMRunner` raises an error instead of silently keeping the old value.
* **Keep `der()` out of `if` branches.** Do not use `der(...)` inside an `if`-expression whose condition contains a parameter; compute the derivative in its own variable first. Otherwise OpenModelica freezes that parameter at compile time. This was fixed in the library's bearing.
* **Keep state selection.** Leave `stateSelect=StateSelect.prefer` on the body coordinates so the linearised states are the physical DOFs.
* **Linearise only in a loaded state.** Contacts must be closed at `t_lin`; `modes()` warns otherwise. Use a backlash of 0.1 µm (not 0, which closes both flanks) and zero clearance for the linearisation only.
* **Extend through the registry.** For new Modelica components (cam–follower, chain, belt …), register a signature and a metrics function with `mp.register(mp.ComponentType(...))`. The notebook has a template.
